# 2026-09-14 — Fase 4: coste de `session/update`, streaming y sesiones paralelas

Presupuestos de ARCHITECTURE.md §29 (Fase 4): overhead por `session/update`
≤ 0,2 ms; 10k tokens/min sin frames perdidos; 4 sesiones paralelas sin
degradar el tecleo.

## Máquina

La misma de `2026-09-13-grid-full.md` (Ryzen 3 5300U, 4c/8t, 14 GiB,
Wayland, gobernador `powersave`), con carga ajena durante la medida
(`load average` 2,8–4,4, navegador abierto). Compilación `--release`.

## Cómo se mide

Las tres escenas abren pestañas de agente **sin proceso** detrás
(`ForgeWindow::open_offline_agent_tab`) y alimentan `session/update`
sintéticos por el mismo camino que el worker ACP (`feed_agent_update` →
`handle_agent_event` → `AgentTab::apply_update`).

- `agent_update_overhead --iterations N`: N updates (cada 25.º un
  `tool_call_update`) aplicados en bloque en el hilo de UI; cada muestra es
  un `handle_agent_event`, sin render.
- `agent_stream --iterations N`: el panel de agente visible recibe 3
  pseudo-tokens por frame (≈ 10,8k tokens/min a 60 Hz); cada muestra es
  chunk → `present()` (mismo `FrameProbe` que `editor_typing`). Una muestra
  > 16,6 ms sería un frame perdido.
- `agent_parallel_typing --iterations N`: cuatro pestañas de agente en
  segundo plano reciben 3 tokens por frame cada una mientras se teclea en
  el editor activo (archivo Rust de 10k líneas, resaltado activo); las
  muestras son tecla → `present()`, comparables con `editor_typing`.

## Resultados

| Escenario | Iteraciones | mediana | p95 | PSS | Umbral |
|---|---|---|---|---|---|
| `agent_update_overhead` | 5000 | 0,0003 ms | 0,0012 ms | 73 MiB | ≤ 0,2 ms ✓ |
| `agent_stream` | 300 frames | 1,9 ms | 2,4 ms | 76 MiB | ≤ 16,6 ms ✓ (0 frames perdidos) |
| `agent_parallel_typing` | 300 teclas | 3,5–3,7 ms | 4,8–4,9 ms | 98 MiB | ≤ 3,0 ms ✗ (ver nota) |
| `editor_typing` (referencia, mismo momento) | 300 teclas | 3,4–3,5 ms | 4,3–4,7 ms | 90 MiB | ≤ 3,0 ms ✗ (ver nota) |

Tres pasadas alternadas de `editor_typing` / `agent_parallel_typing`:
la diferencia de mediana está entre −0,1 y +0,2 ms y la de p95 entre +0,1
y +0,4 ms, dentro del ruido de la máquina. Las cuatro sesiones en streaming
**no degradan el tecleo** de forma medible.

Nota: el propio `editor_typing` está hoy por encima del umbral de 3 ms
(2,7 ms de mediana cuando se midió en Fase 3 con la máquina descargada).
La causa es la carga ajena y el gobernador; se repite en R1/R2 (§5.2)
antes de dar el umbral por incumplido.

## Reproducir

```bash
cargo build --release -p forge-gui -p forge-bench
cargo run --release -p forge-bench -- agent_update_overhead --iterations 5000 --check
cargo run --release -p forge-bench -- agent_stream --iterations 300 --check
cargo run --release -p forge-bench -- agent_parallel_typing --iterations 300 --check
cargo run --release -p forge-bench -- editor_typing --iterations 300 --check
```
